# 模型接入与配将初版

## 使用步骤

1. 启动服务 `npm.cmd start`，打开 `http://127.0.0.1:8765`，页面下方是“智能配将”。
2. 展开连接设置，填写支持 Chat Completions 的 OpenAI 兼容服务基础地址（如 `https://api.openai.com/v1`）、你账号实际可用的模型 ID 和 API 密钥。当前不是 Responses API 适配器，也不保证所有服务/模型兼容。
3. 设置输出上限参数：OpenAI 侧优先 `max_completion_tokens`；某些兼容服务要求 `max_tokens`，以其文档为准。JSON 模式也需服务支持；HTTP 400 时可核对这些参数。切换参数后保存再测试。
4. 点击保存，再点击“测试已保存的连接”。测试仅发送一句固定消息，不发送角色数据，会有少量调用费用；测试成功不等于配将格式已验证。
5. 新建角色并填写赛季，录入至少3名武将，勾选已核对。额外战法、宝物按实际情况录入核对；战法“可用数量”填写可分配次数。
6. 选择1—5队，填写用途、预算等限制，勾选允许发送资源，再生成建议。
7. 检查错误与待核实事项。历史结果基于当时资源快照，修改资源后重新生成。

## 配置与密钥

- `config/model.local.json` 保存模型配置和本地密钥，已加入 Git 忽略；它是本地明文文件，暂未接入 Windows 凭据管理器。不要分享该文件。
- 密钥保存后不回显；留空保留原值，勾选清除删除本地密钥。
- 可用 `STZB_MODEL_API_KEY` 环境变量覆盖本地密钥，需重启服务生效；清除文件密钥不清除环境变量。
- 更换服务商域名时必须重新填写或清除原文件密钥。环境变量密钥由用户自行管理，不随页面清除。
- 模型独立配置替代原先 `config/local.json` 中尚未启用的 model 占位字段；MySQL 配置保持原位。
- 基础地址只接受 HTTPS 云服务或 HTTP 本机服务，不跟随重定向；API 密钥不发送到网页以外的来源，后端仅发送至用户配置的服务地址。

## 发送与保存范围

模型接收赛季、用途以及当前角色已核对资源的名称、ID、属性；不发送角色名、服务器、游戏登录凭证、数据库连接信息或图片。配将及测试通过后端发送，不从前端直连服务商。

MySQL recommendations 表保存角色资源快照、目标、模型名、基础地址、提示词版本、输出、校验结果及服务商报告的 token 用量，不保存 API 密钥。当前角色 JSON 导出仅含资源，不包含模型配置、修改历史或配将历史。查看最近20次结果；语法正确但资源校验失败的建议也保留并明确显示未通过。

## 校验范围和限制

- 检查输出 JSON 格式、队伍数上限、每队3人、站位、资源 ID 与类型、武将/宝物实例重复，以及额外战法重复和可用次数。
- 战法可用数量缺失或无法解释时保守按1次，明确填写0时禁止使用。当前占用不自动推断。
- 模型允许少配队并解释缺口，不虚构资源；没有武将版本关联图、赛季/COST规则库、技能冲突或已审核游戏机制资料，因此不能称为完整游戏规则校验。
- 目前推荐基于模型知识，未接入资料检索、战斗模拟和战报评估。理由和加点建议需人工确认，不输出经过验证的胜率结论。
- 手动限时10—180秒，输入限制为120000字符（不等于 token 预算），输出上限128—16000 tokens。全局每次一个模型调用，不自动重试或自动修复，避免重复计费。可取消；取消或超时不保证服务商停止计费。
- 结构无效响应返回错误；请求不自动重试。部分失败调用的 token 用量不可得，当前记录不构成精确费用账单，也没有账户级费用硬限制。
- 资源在调用中发生变化时仍按请求开始时快照保存，不宣称对应最新状态。

## 验证

`npm.cmd test` 覆盖配置、密钥遮蔽、发送确认、提示词数据范围、模型请求参数、响应失败及资源校验。

`node scripts/verify-mysql.mjs` 使用本地模拟模型服务与测试配置（work/），验证连接测试、发送确认、配将调用、MySQL 保存、重启读取及角色隔离；不覆盖真实配置，不调用真实付费服务，完成后清理测试角色和测试配置。真实服务仍需用户填写配置后测试。

协议依据：[OpenAI 结构化输出官方文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。JSON 模式保证能力取决于模型，程序仍执行独立格式与资源校验。
