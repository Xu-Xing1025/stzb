# 本地资源管理（MySQL）

当前实现不依赖模拟器，可先手工维护角色、赛季、武将、战法和宝物。已实现可配置大模型调用、配将与历史保存，使用前需填入真实服务配置，详见 MODEL.md。尚未接入自动扫描和已审核游戏资料库。

## 启动

1. 启动本机 MySQL 服务。
2. 在 `config/local.json` 的 `mysql` 中填写连接信息。当前使用用户指定的本机 root 账号，密码仅存在该忽略提交的文件中；模板不含密码。
3. 首次准备：`npm.cmd ci --ignore-scripts`，随后 `npm.cmd run db:init`。
4. 运行 `npm.cmd start`，浏览器访问 `http://127.0.0.1:8765`。终端保持运行，Ctrl+C 停止。

初始化会创建独立的 `stzb_assistant` 数据库及 roles、resources、resource_changes 表，不访问其他业务数据库。当前无旧数据库迁移需求；历史方案中的 SQLite 未用于持久化资源，本版本不依赖 SQLite。

## 使用

- 新建角色，填写服务器和赛季；后续可修改。
- 切换武将、战法、宝物，新增或编辑资源。未知属性留空，可在其他属性 JSON 中补充详细信息。
- “已核对”只表示用户确认，不表示账号已完整录入。
- 删除前需要确认；资源更新和删除写入数据库修改历史；角色切换后显示各自资源。
- 导出当前角色为 JSON 文件，保存到安全位置；导入创建新的独立角色，不覆盖已有数据。
- JSON 资源备份不含审计历史，完整数据库备份请使用 MySQL 备份工具。角色元数据暂不记录修改历史。

## 验证

- `npm.cmd test`：输入格式校验。
- `node scripts/verify-mysql.mjs`：真实 MySQL 保存、重启持久化、角色隔离、版本冲突、导入导出和接口防护验证。占用 18765 端口，新建测试角色，完成后删除测试数据。

## 当前实现取舍

现有 Node.js 可用，因此资源管理采用 Node.js + mysql2 + 原生网页，安装锁文件固定依赖；先完成可用闭环。Python 采集助手可后续独立接入。早期 React/FastAPI/SQLite 组合为规划，当前以本文件为准。
