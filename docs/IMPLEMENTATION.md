# 实施计划与验收

## 已确定范围

Windows 单人本地使用；优先适配 MuMu 单实例和一种固定分辨率。资源覆盖武将、战法、宝物和赛季，允许人工维护。最终支持单队及多队推荐。

## M0：环境与实机小样

- 确认 MuMu 版本、安装目录、ADB 启用方式、连接地址、分辨率。
- 确认官服/渠道服与手机账号能否访问同一角色。
- 安装可运行的 Python，创建项目专用虚拟环境。
- 在用户登录后连接指定实例，仅采集一张画面，保存到 `data/captures/`。
- 实机确认资源列表和详情页面的实际字段，不能仅按攻略推断。

验收：指定实例可识别；画面非黑屏、清晰；设备未连接时给出明确提示。不自动操作其他模拟器实例。

## M1：账号资源维护闭环（首个可用版本）

- 建立角色、武将、战法、宝物、赛季和修改记录的数据表。
- 实现资源列表、增删改查、核对状态与账号切换。
- 提供结构化 JSON 导入导出；导入校验、事务写入，失败不破坏原数据。
- 数据库版本迁移与升级前备份。

验收：重启后数据仍在；导出再导入字段一致；不同角色不混用；非法输入有明确提示。

## M2：扫描和核对

- 实现页面状态判断、画面稳定等待、重叠翻页、重复检测、进度和取消。
- 按资源类型逐个适配，先武将，再战法、宝物、赛季。
- 详情页补采；异常弹窗、加载超时或无进展时暂停。
- 扫描结果先写 observation，再与已确认资源合并。
- 展示新增/差异/未确认项及原图，人工决定是否采纳。
- 支持从已保存进度恢复；不把“扫描结束”等同于“完整”。

验收：使用人工标注的实机小样统计资源漏扫率、名称准确率、属性准确率。明确统计分母和未识别项；首轮测量后制定门槛，不预先宣称准确率。

## M3：游戏资料与规则

- 每条资料记录来源、适用版本、更新时间和审核状态。
- 为武将/战法/宝物建立稳定内部 ID；名称和外观不能作为唯一 ID。
- 区分已拥有、已解锁、可学习、当前占用等状态；具体语义根据游戏页面确认。
- 先实现资源归属、武将/战法/宝物占用冲突；其他规则在明确机制后加入。

验收：每条校验错误能定位到队伍和资源；未知机制不作为已验证规则。

## M4：接入大模型

- 模型提供商、服务地址和模型名可配置；密钥不放在前端或导出文件。
- 设置请求超时、取消、有限重试、用量记录和调用预算。
- 输入为已确认账号资源、相关资料、用户目标和锁定队伍。
- 使用结构化响应；无效输出拒收，规则不通过时有限次数修正。
- 保存输入资源快照、资料版本、模型配置标识和校验报告。

验收：缺少密钥、网络超时、结构错误、未知资源、队伍冲突均有可解释结果；未经验证不显示胜率或“最强”结论。

## M5：安装交付

- 提供安装/启动入口、首次引导、诊断日志和备份恢复。
- 在无开发环境的 Windows 上验证安装、启动、数据维护、扫描和配将。
- 明确运行所需网络、模型服务费用及实际支持的 MuMu 版本/分辨率。

## 后续可选

多人账号、云端同步、战报分析及其他模拟器均在本地闭环通过后评估。当前不做游戏内自动装配或其他游戏操作。

## 待实机确认

- MuMu 版本、安装路径、ADB 地址与分辨率。
- 游戏客户端渠道及角色一致性。
- 资源详情字段、列表排序/筛选和总数是否可读取。
- 模型服务选择、图像是否允许发送至云端、调用预算。

## 日常开发顺序

每次完成一个可用小步骤，再做相应验证。第一项功能为 M1 的“新建角色并手动维护武将”，同时进行 M0 的 MuMu 连接验证。自动扫描和模型分析均提供独立适配层，避免依赖未完成模块。
