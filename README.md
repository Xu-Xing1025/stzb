# 率土配将助手

Windows 本地优先的账号资源管理与智能配将项目。首个模拟器目标为 MuMu。

## 当前状态

项目准备阶段：已提供开发路线、数据规范、配置模板与环境检查脚本。尚未实现资源管理页面、MuMu 扫描、OCR 或模型配将；没有连接或操作游戏。

## 使用目标

用户自行在 MuMu 登录游戏 → 扫描资源 → 人工核对 → 保存账号资源 → 根据游戏资料和用途生成配将方案 → 程序校验 → 保存结果。

## 开始准备

1. 安装并启动 MuMu，在模拟器内安装游戏，确认你的手机账号能在该客户端登录到同一角色。登录和验证码由你完成。
2. 在项目目录运行环境检查：

   ```powershell
   powershell -NoProfile -File .\scripts\check-environment.ps1
   ```

3. 根据检查结果准备 Python 开发环境；若脚本只报告 WindowsApps 别名，则尚未确认有可运行的 Python。
4. 在 MuMu 的设置或安装目录中确认 ADB 的启用方式、程序路径与连接地址。不同版本可能不同，不预设固定端口。
5. 将 `config/local.example.json` 复制为 `config/local.json`，填写真实的 ADB 路径、设备序列号及采集分辨率。该文件已加入忽略规则。
6. 按 `docs/IMPLEMENTATION.md` 从 M1 开发。本阶段无需模型密钥；开发模型适配模块时再配置密钥，勿将密钥提交到仓库。

## 技术方向

- 前端：React + TypeScript。
- 后端与采集：Python + FastAPI；后续安装依赖时锁定版本。
- 存储：单人版 SQLite，核对画面保存在本地文件目录。
- 识别：OCR、页面定位、必要时视觉模型补充；选择具体引擎前先用实机画面验证。
- 配将：带来源与版本的游戏资料 + 候选生成 + 大模型分析 + 确定性约束校验。

目前没有安装上述框架或下载模型。优先做本地闭环，不部署云端。

## 开发约定

- 账号资源与全游戏图鉴分开存储；所有资源归属明确的账号和角色。
- 扫描观察值与已确认值分开；扫描结果不能直接覆盖人工维护数据。
- 扫描中断或资源缺失不自动删除数据。
- 游戏知识没有资料时标记未知，不由模型编造机制或胜率。
- 本地服务默认仅监听 `127.0.0.1`。
- 不保存游戏密码或验证码；游戏登录由用户完成。
- MuMu 接入先做设备检测与单帧采集，再适配翻页，不能宣称已有完整扫描能力。

详见 [实施计划](docs/IMPLEMENTATION.md) 与 [数据规范](packages/contracts/README.md)。
