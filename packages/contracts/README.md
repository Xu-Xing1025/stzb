# 数据规范草案

这份文件是开发约束，尚不是已实现的数据表或 API。实机确认后再定义严格 schema 和迁移文件。

## 核心实体

| 实体 | 核心字段 |
| --- | --- |
| role | id、显示名、服务器、游戏角色标识（可空）、客户端渠道、赛季资料 |
| catalog_entry | id、类型、名称、变体、属性、来源、适用版本、审核状态 |
| owned_resource | id、role_id、catalog_id、类型、属性、核对状态、revision、更新时间 |
| scan_job | id、role_id、设备标识、扫描类型、状态、断点、完整性状态、起止时间 |
| observation | id、job_id、候选资源、原始识别字段、画面路径、采集时间、识别器信息、处理状态 |
| resource_change | id、资源标识、修改前后值、来源、时间、对应 observation |
| recommendation | id、role_id、输入快照、用户目标、资料版本、模型配置标识、方案、校验报告、时间 |

## 字段语义

- 游戏内 ID 未确认时使用本地 ID，不能把猜测值当作官方 ID。
- 同名不同版本武将与多个宝物实例必须能独立记录。
- 缺失属性使用 null 或明确 unknown，不能默认当作 0、未拥有或已删除。
- 识别置信度如有提供，保留产生方式；不将模型自报数值视作统计准确率。
- 所有持久化资源属于明确 role_id；合并和配将不得跨角色引用。
- 记录时间使用带时区的时间戳，界面按用户时区展示。
- 资料版本与账号所属赛季分别保存。

## 合并规则

1. 每次扫描新增 observation，不直接修改已确认资源。
2. 新资源作为待核对项；重复画面不重复创建资源实例。
3. 已有资源有差异时，产生差异项；人工选择接受、忽略或手动编辑。
4. 更新携带 revision，避免扫描与人工操作互相覆盖。
5. 本次没找到的资源标记为未观察到，不自动删除。
6. 所有修改可追溯，删除需要明确用户操作并保留记录。

## 配将边界

模型只引用输入快照中的资源 ID；输出名称仅供展示。缺少关键属性时报告缺失字段。方案保存时记录校验覆盖范围；账号资源变化后原方案标记为需要重新校验。
